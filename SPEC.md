A web "office sitcom" that runs live: one shared virtual tech company (code + sells software) with 10 AI
employees who work, slack off, gossip, get caught by the boss, get warned/fired by HR, get replaced by newly
interviewed hires — all in real time. Dialogue is generated by an LLM (free Gemini → free Groq fallback → offline
templates; OpenAI optional, all via the OpenAI-compatible API) at "interesting moments" only, so token cost stays low. Later the site earns money via Shopee affiliate links mentioned naturally in the story.

All user-facing text is **Vietnamese with full diacritics**. Code comments: short, Vietnamese or English.

Source of truth for data shapes: **`src/types.ts`** (do not change shapes; if you must, explain in your report).
Already written and stable: `src/config.ts` (env config `CONFIG`), `src/types.ts`, `src/sim/map.ts` (office map,
`DESKS`, `SPOTS`, `FURNITURE`, `ROOMS`, `WALLS`, `findPath`, `isWalkable`, `roomAt`, `MAP_DATA`; v2 map = phòng trưng bày +
WC kín, xem §1.2). Các thay đổi v2 (phòng trưng bày / showroom, giao diện mới) được chốt trong `docs/v2-contract.md`;

## 0. Principles

1. **One shared world** on the server; browsers are viewers (like a livestream). Token cost does not grow with users.
2. **Two layers**: the "body" (movement, activities, stats, KPI, schedules) is plain code — 0 tokens.
   The "brain" (GPT) is called only to write a whole *scene* (4–10 lines in one JSON response), which is then
   played back line by line with realistic delays, so it *looks* real-time.
3. **Hard token guards**: daily USD budget, min seconds between calls, max concurrency, no LLM for low-priority
   scenes when nobody is watching, static system prompt first (OpenAI auto prompt-cache), compact dynamic prompt,
   offline fallback that never fails.
4. **Never crash the sim**: every async AI call has a timeout + offline fallback. Bad JSON → offline.
5. **No hardcoded dialogue in LLM mode.** The offline generator (templates) exists only as a fallback / preview
   when there is no API key; the UI labels it clearly.
6. No new npm dependencies beyond: `openai`, `ws`, `dotenv` (+ dev: `tsx`, `typescript`, `@types/*`).
   Frontend is vanilla JS ES modules + Canvas 2D, **no build step, no frameworks, no external images**.
7. TypeScript strict, ESM, NodeNext → relative imports end with `.js` (e.g. `import { CONFIG } from '../config.js'`).
   Run with `tsx`. Typecheck: `npx tsc --noEmit`.

## 3. Time model (World)

- `time` = absolute game minutes (float). `day = floor(time/1440)+1`, `minuteOfDay = time % 1440`.
- **compressed** (default): start at day 1 07:30 (time 450). Tick every 100 ms real:
  `time += CONFIG.gameMinutesPerSecond * speed * dt/1000`. `speed ∈ {1,2,5,10}` (dev panel).
  Weekday = `['Thứ Hai','Thứ Ba','Thứ Tư','Thứ Năm','Thứ Sáu'][(day-1)%5]` (no weekends).
  **Night skip**: when minuteOfDay ≥ 18:30 and nobody is present → end of day; at 21:00 force everyone out.
  End of day = compute KPI results → `director.onDayEnd(day, results)` → jump to next day 07:30 → plan the new
  day → `director.onDayStart(day+1)`.
- **realtime** (`TIME_MODE=realtime`): clock follows Asia/Ho_Chi_Minh wall time (speed fixed 1; dev speed
  ignored with a toast). Day index counts from first start (persisted). End of day at midnight rollover.
  Saturday/Sunday: nobody comes (office closed).
- `isNight` = minuteOfDay < 07:00 or ≥ 19:00.

Daily schedule (minute of day):
- Arrivals: diligent 07:40–08:00, normal 07:55–08:20, lazy 08:10–08:50 (late if > 08:30 → `director.onAgentArrived(id, true)`).
  HR 07:50–08:05. Boss 08:40–09:20.
- 09:30 standup (Director). 12:00–13:00 lunch for everyone (pantry table / lounge; a few go out = offsite).
  12:40–13:15 some nap at desk (napping not catchable during lunch).
- Leave: 17:30 + overtime 0–120 min for diligent people or near deadline; lazy leave 17:30–17:35 sharp.
  Boss leaves 17:00–18:30.
- Day start resets: kpiToday 0, caughtToday 0, energy 75–95, stress −25 (min 10), mood regresses 30% toward 60,
  `hidden = false` (không ai còn "trong WC" qua đêm; cũng vậy khi khôi phục từ file).

wifi_down → ×0.3. Targets ≈ 240–300 (`ROLE_INFO.kpiTarget`). Results at end of day: ratio = kpiToday/kpiTarget;
`lowStreak = ratio < CONFIG.kpiLowRatio ? lowStreak+1 : 0`; push `{day, ratio}` into kpiHistory (keep 14).
Boss and HR get KPI shown but are never warned/fired.

**Company** (World): project progress += 0.016 × KPI points produced by techlead/senior/junior/qa/designer;
at ≥ 100 → `projectsDone++`, `director.onEvent('release', { note: projectName })`, next project from
`PROJECT_POOL` with `deadlineDay = day + 4..6`. Sales agents while working/window: chance per game minute
`0.004*(0.5+diligence)` to close a deal → revenue += 10–80 (triệu), kpiToday += 40,
`director.onEvent('deal', { agentId })`. Revenue resets every 20 days ("tháng"), target 1500.

**Boss**: arrives, mostly `boss_office`, `patrol` (weight 0.35, cooldown 60). World plans 0–2 away trips per day
(≥1 with 60%) between 09:30–15:30, 60–150 min, reason from `BOSS_AWAY_REASONS`. Leaving: walk to entrance →
`present=false`, activity `away`, `bossAway()=true` → `director.onBossLeft(reason)`. Returning: appear at entrance,
`bossAway()=false`, **panic switch**: every present, non-scene agent with a catchable activity instantly switches
to `working` with emote 😰 and label "giả vờ làm việc" (10–20 min) → then `director.onBossReturned()`.
Dev events `boss_leave` / `boss_return` force these. While boss is present and walking, each tick check agents
within 4.5 tiles doing a catchable activity (not in a scene) → `director.onSlackerSpotted(bossId, victimId)`
(per-victim cooldown 90 game min, global 30 game min).

**Lifecycle helpers** (`WorldApi`): `addAgent` (spawns at a point, relationships initialized to 0 both ways with
note "người mới"), `fireAgent` (status fired, emote 📦, label "ôm thùng đồ ra về", walks to entrance, then removed;
its desk becomes empty), `hireAgent` (candidate → active, today's schedule, walks to desk), `dismissCandidate`.
`visitorSpot(targetId)` returns a walkable tile next to the target's seat (or current position) not already used
as another agent's target. `reserveSpot` keys look like `'coffee:0'`.

World is the **only** place that emits `frame` (every 200 ms), `agents` and `status` (every 2 s), keeps the log
history (last 200 entries, sent in `hello`), and assigns LogEntry ids/day/minute. `World.log()` broadcasts
`{t:'log', entry, bubble}`.

### 5.2 Scheduling

- Concurrency: at most **1 office scene + 1 online scene** at a time. High-priority/scheduled scenes queue and
  start as soon as the slot is free (they wait; they don't interrupt).
- Spontaneous check every ~2 s real when the relevant slot is free: build weighted candidates (co-location 3,
  desk_visit 2, gossip 1.5×gossip trait, group_chat 1 (×3 for ~2 game h after boss left / firing / payday),
  company_chat 0.3, pingpong_match if two at pingpong, confront 2 when available) → pick → `brain.reserve(priority)`
  → `null` means skip (do nothing). Granted → create scene.
- Per-agent cooldown: not in a low-priority scene within 60 s real of its last scene (`lastSceneAt`).
  ≥ 3 s pause after an office scene ends; low-priority online scenes ≥ 45 s apart.
- Fixed schedule (absolute game times): standup 09:30, lunch 12:05, HR actions 10:00+, interviews, boss_call at random
  times, random daily events: server_down (25%/day), wifi_down (15%/day), birthday (~every 4 days),
  payday every 20th day 15:00. Preconditions not met (people absent / busy) → retry for up to 60 game min, then drop.
- **showroom_chat tự phát (v2)**: mỗi nhịp kiểm tra, nếu `findShowroomGroup()` thấy ≥ 2 người rảnh, đã tới chỗ, đứng trong phòng
  trưng bày (spotKey `showroom_*`, hoặc đứng cạnh SPOTS showroom, hoặc trong phòng `showroom` với activity `showroom`) → ứng viên
  trọng số 3 (ngang "tình cờ đứng cùng chỗ"), ưu tiên nhóm cùng một kệ; 3 người với xác suất 0,55.
- **showroom_chat theo lịch (v2)** (`planDay`): từ 09:20–10:40 cứ 120–180 phút game một mục `showroom_chat` (prio normal, cửa sổ 45
  phút, né 11:45–13:10, chỉ khi `SPOTS.showroom_*` tồn tại). Khi đến hạn: đã có ≥ 2 người ở đó → diễn ngay; chưa → `sendToShowroom()`:
  chọn marketing (80%) hoặc người nhiều chuyện/lười làm "đầu tàu", gom nhóm 2–3 người thân (`pickFriendsGroup`), chọn kệ theo
  `preferredShelf(lead)`, `reserveSpot(showroom_*)` + `setActivity('showroom', 8–12 phút, { target, label, emote 🛍️ })`; những người
  này được "giữ chỗ" (không bị cảnh low/normal khác kéo đi) tối đa 14 phút game; đủ người tới nơi → diễn; không tới kịp / bỏ đi → bỏ
  mục. Nếu World không nhận activity `showroom` (lệnh bị bỏ qua) thì trả chỗ, không mời nữa. **Tốc độ tua**: cả hai cửa sổ được đổi
  sang phút game theo tốc độ hiện tại (`realSecToGameMin`): thời gian đứng ở kệ không dưới ~10 s thật, hạn chờ tới nơi không dưới ~15 s
  thật — ở x10, 14 phút game chỉ là 2,8 s thật, không đủ đi từ bàn qua kệ (phát hiện khi chạy thử; x1 không đổi).
- **Cap riêng (v2)**: tối đa **1 showroom_chat / 30 phút THẬT** (env `SHOWROOM_SCENE_MIN_MINUTES`, mặc định 30, `0` = bỏ), tính từ
  lúc dựng cảnh (kể cả bị huỷ) để không dồn; khởi động có 2 phút "warm-up" như sản phẩm. Khi chưa hết cap: cảnh tự phát không được
  đề xuất, mục theo lịch chờ (hết cửa sổ thì rơi) và **không** mời ai qua.
- Cảnh showroom bỏ qua nhịp sản phẩm thường (`PRODUCT_MENTION_MIN_MINUTES`, xác suất 50%) vì sản phẩm là bắt buộc, nhưng khi câu
  `product: true` được phát thì vẫn cập nhật `lastProductAt` / `recentProducts` / `productLock` như mọi cảnh có sản phẩm.
- **Người `hidden` (đang trong WC) không bao giờ được chọn vào BẤT KỲ cảnh nào** (`free()`); đang trong cảnh mà `hidden` bật →
  cảnh bị huỷ (`sceneValid`).
- `COUNTED` thêm `showroom` → "ghé phòng trưng bày ngắm đồ N lần" trong bối cảnh / mầm tin đồn.

### 5.3 Scene lifecycle (Director-private `Scene` object)

1. **create**: set each participant `sceneId`; office channel → `world.setActivity(id, 'scene', 600, { target, label:'đang nói chuyện', emote:'💬' })`
   (no target = stay in place); online → `onPhone = true` (activity untouched). Build `SceneRequest`, build
   `PromptContext`, start `brain.generateScene(req, ctx, via)` immediately (generation overlaps with walking).
2. **gathering**: wait until all office participants `isArrived()` **and** result ready. After 45 s real teleport
   stragglers to their spots. If the result isn't ready after 35 s, abort (brain itself times out at ~25 s).
3. **playing**: emit `scene` start (+ a `scene_start` log entry) when the first line plays. For each line:
   `world.log({ kind:'line', channel, sceneId, speaker, speakerName, text, icon: emote, product? }, { durationMs, nextSpeaker })`;
   speaker faces listeners. `durationMs = clamp(1600 + 55*text.length, 2200, 7500) / min(speed, 3)` (online ×0.8);
   next line after `durationMs + 300`.
4. **end**: apply effects with clamps (relationship ±15 and only among participants/aboutId, mood ±15,
   kpi ±25 only if allowed, memories ≤ 120 chars for participants), handle rumor/verdict, push summary to
   `recentSummaries` (keep 12) and to today's events (keep 40), emit `scene` end with summary, release: `sceneId=null`,
   `onPhone=false`, `releaseSpot`, `setActivity(id,'idle',0)` for office participants, `lastSceneAt=Date.now()`,
   run the type's `onEnd` hook (firing → `fireAgent`, interview → hire/dismiss, hr_warning → `warnings++`).
5. **abort**: if a participant is fired/gone/not present → release everyone, no effects.

Director may directly mutate these AgentState fields: `sceneId`, `onPhone`, `warnings`, `lastSceneAt`,
`caughtToday`. Everything else goes through `WorldApi`.

### 5.4 Rumors ("tam sao thất bản")
- Gossip: 60% continue an active rumor (teller = someone present who heard it; listener = present non-hearer, not
  the subject) else start a new one about `aboutId`. `req.rumor = { id, aboutId, currentText, isNew }`.
- Result `rumor.text` = the version as told now → new Rumor or push a `RumorVersion`; listener added to `heardBy`.
- Once heard by ≥ 3 people, 30% chance per check that the subject "nghe phong thanh" → `confront` with the latest
  teller; rumor becomes inactive after. Keep ≤ 12 rumors. Emit `{t:'rumors'}` on change.

### 5.6 HR flows (v3 — viết lại; thiết kế gốc `docs/v3-news.md`)

Không còn luật cứng `lowStreak ≥ kpiFireDays → firing`. Quyết định do **AI đưa ra trong cảnh `hr_review`**, code chỉ làm **hàng rào** và
thi hành. `KPI_WARN_DAYS` / `KPI_FIRE_DAYS` = mốc tối thiểu của hàng rào + điểm neo của chính sách offline.

Giữ từ v1/v2: `onDayEnd(results)` vẫn viết bản tin qua `brain.generateRecap` (async) → store (keep 14) → emit `{t:'recap'}` + log event
"📰 Bản tin ngày N đã lên sóng". Phỏng vấn: `await brain.generateCandidate(...)` → `world.addAgent(candidate,'candidate', SPOTS.entrance[0])`
→ cảnh ở phòng họp → verdict `hired` → `world.hireAgent` + toast "🎉 Chào mừng {name} gia nhập!" + lịch `welcome`; `rejected` →
`world.dismissCandidate` + phỏng vấn lại hôm sau (sau 2 lần trượt thì ép `hired`). Sếp vắng → phỏng vấn / cho nghỉ chỉ có HR.

#### Hồ sơ (`req.hrDossier[]`, `buildDossier`)
Mỗi nhân viên (không sếp / HR, status active): `kpiRatios` 7 ngày, `lowStreak`, `warnings`, `caughtToday`, `hiredDay`, `mood`, `stress`,
`attitude` (≤ 160: bị bắt lười, tâm trạng, đang thử thách, 3 ký ức gần nhất), `allowed` = `allowedActions(a, cfg, ledger, env)`.
Sắp theo độ "đáng lo" (lowStreak + warnings) giảm dần.

#### Hàng rào (`allowedActions`, `src/sim/hr.ts`)

| action | điều kiện (tất cả phải đúng) |
|---|---|
| `none` | luôn |
| `warn` | lowStreak ≥ 1 |
| `probation` | lowStreak ≥ 1, không đang thử thách (`probationUntilDay ≤ day`) |
| `second_chance` | lowStreak ≥ 1 hoặc warnings ≥ 1 |
| `fire` | lowStreak ≥ 2 **và** (warnings ≥ 1 **hoặc** lowStreak ≥ `KPI_FIRE_DAYS`) **và** day − hiredDay ≥ 3 **và** day − `ledger.lastFireDay` ≥ 2 **và** không có cảnh firing/layoff đang chờ (`env.firePending`) |
| `praise` | KPI TB 7 ngày ≥ 1.0 (≥ 2 ngày số liệu), day − lastPraiseDay[id] ≥ 3, day − lastBonusDay[id] ≥ 2 |
| `bonus` | KPI TB 7 ngày ≥ 1.0 (≥ 2 ngày), day − lastBonusDay[id] ≥ 7 **và** day − `ledger.lastBonusAnyDay` ≥ 7 (toàn công ty — không thưởng 2 người cùng tuần, `docs/v3-news.md`) |
| `promote` | KPI TB ≥ 1.15 trên ≥ 5 ngày, thâm niên ≥ 10 ngày, day − `ledger.lastPromotionDay` ≥ 7 (toàn công ty), không có cảnh promotion đang chờ |
| `layoff` | `ledger.lowRevenuePeriods ≥ 2` (kỳ = lần họp cách nhau ≥ `HR_REVIEW_EVERY_DAYS`, doanh thu < 50% **nhịp** mục tiêu), thâm niên ≥ `LAYOFF_MIN_TENURE` (10), cùng cap `lastFireDay` với fire, `layoffsInMonth < MAX_LAYOFFS_PER_MONTH` (2 đợt / `MONTH_DAYS`) |
| `open_position` | doanh thu ≥ 80% nhịp, `headcount < 12`, chưa có vị trí trống, còn bàn trống (`freeDesks`: key `DESKS` không ai ngồi / giữ) |

**Nhịp doanh thu** (`revenueRatio`): `revenueMonth / (revenueTarget × max(dayInMonth, 2) / MONTH_DAYS)` với `MONTH_DAYS = 20` (khớp World).
1.0 = đúng nhịp; ngày 1–2 tính như ngày 2 để không ai thấy "0%".

#### Kiểm tra quyết định (`validateDecisions`)
Hành động phải ∈ `allowed` của người đó (`none` luôn qua); mỗi người 1 quyết định (mục đầu); ≤ 1 `fire`/`layoff`, ≤ 1 `promote`,
≤ 2 `praise`/`bonus` mỗi lần họp; `open_position` là quyết định chung (id rỗng) chỉ khi có ai được phép đề xuất; ≤ 4 quyết định khác `none`.
Bị gác lại → `log kind:'hr' ⚖️ "<HR> ghi sổ: sếp đổi ý về "<hành động>" cho <ai> — để kỳ sau (<lý do>)"` (người xem đã nghe lời hứa trong thoại nên
được kể vì sao không thành). Prompt hr_review ghi rõ **TRẦN 1 LẦN HỌP** (≤ 4 quyết định khác none, ≤ 1 fire/layoff, ≤ 1 promote, ≤ 2 praise+bonus)
và yêu cầu thoại nói tiếng Việt (không đọc mã action). Trước khi thi hành, Director tính lại `allowedActions` với số liệu lúc đó (hàng rào lần hai).
`sanitize.ts` (AI text) đã lọc một lần theo `allowed` trước khi tới Director (§6.4).

#### Nguồn quyết định
- `res.source === 'llm'` → dùng `res.hrDecisions` (mảng rỗng hoặc thiếu / sai dạng = AI quyết "chưa động tới ai"; không bao giờ rơi về chính sách offline khi AI đã viết cảnh).
- Không có AI → `offlineDecisions(dossier, cfg, { revenueRatio })` của Director (ngẫu nhiên có trọng số, **leo thang** quanh
  `KPI_WARN_DAYS` / `KPI_FIRE_DAYS`: chưa bị nhắc → nhắc là chính; đã bị nhắc mà lowStreak vượt `KPI_FIRE_DAYS` → cho nghỉ có xác suất
  cao dần nhưng không bao giờ 100%; người tốt phần lớn kỳ không ai nhắc tới — khen 0.45 / thưởng 0.3 so với "không làm gì" 2.5).
  Quyết định kèm trong thoại mẫu offline (`bHrReview`) chỉ là lời dẫn, không được thi hành.

#### Thi hành (`applyDecision` → `executeDecision`)
| action | hiệu ứng |
|---|---|
| warn | enqueue `hr_warning` (+5–20 phút, cửa sổ 150, high); kết: `warnings++`, `ledger.lastWarnDay`, drift diligence +0.01/ngày × 3 ngày, boost `after_warning` |
| fire | enqueue `firing` (+10–30 phút, cửa sổ 150); kết → `depart(emp,'fired')` — `ledger.lastFireDay = day` ghi **khi cảnh diễn xong** |
| layoff | enqueue `layoff`; kết → `depart(emp,'laid_off')` (ghi `lastFireDay`, `layoffDays`) |
| probation | `world.setProbation(id, day + 5)`, mood −6 / stress +8, memory, desk_visit HR→emp (`hr_probe`), boost `after_probation` |
| second_chance | mood +5 / stress −4, memory, log 🤲 |
| praise | `ledger.lastPraiseDay`; enqueue `boss_call` reason `praise` (targetId + note); kết: drift ambition +0.02 |
| bonus | `ledger.lastBonusDay`, `world.grantBonus`, mood +12, memory, toast 💰, celebration `bonus` (centerId), company_chat `bonus` 50%, drift ambition +0.02 |
| promote | enqueue `promotion` với `newLabel = promotedLabel(a)`; kết (`afterPromotion`) → `setRole` + `ledger.lastPromotionDay = day` |
| open_position | `extraVacancy(w, bàn trống, day)` (vai trò theo nhu cầu: junior/qa khi dự án chậm, salesnew…, `Vacancy.extra = true` → không bị coi là "vai trò đã có người"), enqueue `interview` 14:00 hôm nay / 09:45 mai; hết bàn → log hệ thống "tạm gác" |

**Cảnh thi hành không diễn được** (người vắng / bận hết cửa sổ, hết ngày): `deferDecisionScene` xếp lại **sáng mai 09:20–10:20** (≤ 2 lần),
log 'hr' ⏸️ "Hoãn <cho nghỉ việc|cắt giảm|thăng chức> <tên> sang sáng mai: <lý do>" + archive `hr {deferred:true}`; hết lượt / người đã rời →
log ⚖️ "Quyết định … bị huỷ" + archive `hr {cancelled:true}`. Trong lúc chờ, `env.firePending` / `promotionPending` khoá fire/layoff/promote mới.
Bản ghi archive của cuộc họp là `⚖️ Chốt họp xét nhân sự: …` (`pending: [id]` cho các quyết định chờ cảnh).

**`depart(emp, reason)`** (thay `afterFiring`): ghi `departed` (để Brain còn tra tên 3 ngày), `world.removeAgent(id, reason)`
(World v3; chưa có thì `fireAgent`), drop mạch truyện có người đó, `firedToday`, vacancy + lịch phỏng vấn: fired → 14:00 hôm nay /
09:45 mai; resigned → 09:45 sau 1–2 ngày; laid_off → không tuyển (vai trò đóng băng 6 ngày **và** chừng nào còn kỳ doanh thu kém: `inSlump()` =
`lowRevenuePeriods ≥ 1` hoặc vùng doanh thu `low` → `sweep` không `detectVacancies`, không `ensureInterviews`; fired trong kỳ kém → vacancy chờ,
log hệ thống "để trống chờ doanh thu khá lên"). Log 📦 / 📉 / 🚪, memory mọi người,
bạn thân mood −6 (−10 khi tự nghỉ), group_chat `after_firing` / `after_layoff` / `after_resign`, company_chat tương ứng, archive.

**Cuối ngày (`endOfDayHr`)**: `lowMoodDays[id]` = số ngày "chán việc" liên tiếp (mood < 40 **hoặc** stress > 70 **hoặc** ghét sếp ≤ −20 **hoặc**
đã bị nhắc mà lowStreak ≥ 1; mood đêm nào cũng hồi về 60 nên ngưỡng 25 cũ không bao giờ chạm); sếp vắng ≥ 180 phút và `caughtToday === 0` → drift
laziness +0.01; `reviewTriggers` (lowStreak ≥ 2 / đã nhắc mà vẫn thấp / chán việc ≥ 3 ngày) + `revenueTrigger` (chỉ khi vùng doanh thu
ĐỔI: rơi < 50% / vượt > 120% nhịp, một lần mỗi lần đổi) → không phải ngày định kỳ thì enqueue `hr_review` 10:00–10:45 mai + log 📒.

**Xin nghỉ (`planStoryScenes`)**: chán việc ≥ 2 ngày **và** (ghét sếp ≤ −15 / đã bị nhắc / mood < 45) → 35% enqueue `resign_talk` (≤ 1 người/ngày,
cách lần trước ≥ 5 ngày). Beat `resign_threat` của biên kịch (`resign_check`): xác suất nói chuyện thật với HR = 0.15 + 0.25 (đã bị nhắc)
+ 0.25 (ghét sếp ≤ −10) + 0.2 (chán việc ≥ 1) + 0.15 (mood < 50), kẹp 0.15..0.85; không thì HR ghé hỏi han.

**Hết hạn thử thách (`resolveProbations`, đầu ngày)**: `probationUntilDay < day` → KPI TB 5 ngày ≥ `KPI_LOW_RATIO` = **qua** (mood +8, drift diligence
+0.02, HR ghé báo tin, log ⏳ "hết hạn thử thách KPI — qua") / **không qua** (mood −8, log ⏳ "… không qua, HR xin họp sếp sớm" + enqueue `hr_review`
hôm nay để AI quyết tiếp); `world.setProbation(id, null)`; archive `hr {action:'probation', passed}`. `attitudeOf`/prompt chỉ nhắc thử thách còn hiệu lực.

**Xin tăng lương**: `askedBefore` = đã từng bị từ chối (`ledger.raiseDeniedDay[id]`, ghi khi verdict denied) → tình huống "lần trước đã xin và bị từ chối".

**Verdict khi AI không chốt** (offline / null): resign_talk `P(leave) = clamp(0.35 + (25 − mood)/100 + max(0, −30 − bossScore)/200, 0.2, 0.75)`;
raise_request `P(approved) = clamp(0.25 + (avg − 1)×1.5 + (revenueRatio − 0.8)×0.5 + relScore(boss→emp)/200, 0.1, 0.8)`.
approved: mood +20, memory, 50% `kpiTarget × 1.05` (đặt thẳng, không qua setRole để khỏi tính thăng chức), drift ambition +0.02;
denied: mood −10, relationship emp→boss −10, memory. stay: mood +10, relationship emp→HR +6, `lowMoodDays = 0`.

**Dev event `hr_review`**: ép `hr_review` ngay (prio high, `force`), log ⚖️ "HR rà soát KPI: mời sếp họp xét nhân sự ngay — <người kém nhất>".
Đang họp rồi → log "HR rà soát KPI: HR và sếp đang họp…".

**Sổ HR (`HrLedger`, lưu trong `director.serialize().story.ledger`)**: `lastReviewDay, lastRevenueCheckDay, lastFireDay, lastPromotionDay,
lastBonusAnyDay, lowRevenuePeriods, layoffDays[], lastRevenueZone, lastBonusDay{}, lastPraiseDay{}, lastWarnDay{}, lastRaiseAskDay{}, raiseDeniedDay{},
lastResignTalkDay{}, lowMoodDays{}, frozenRoles{}, reviews, decisions, rejected`; `pruneLedger` bỏ người đã rời. `restore` giữ `Vacancy.extra`
(vị trí mở thêm không bị gộp theo vai trò).

### 5.7 Events (`onEvent`)
server_down (incident scene + `setIncident('server_down')`, cleared 30–60 game min later; dev stress +15),
wifi_down (`setIncident('wifi_down')` 20–40 game min, group_chat about it), payday (mood +15 all, company/group chat,
product boost), birthday (celebration at lounge), deal (toast "💰 {name} vừa chốt hợp đồng!", maybe celebration or
company_chat), drama (force a gossip/confront now), release (celebration 70% / incident 30% "bug production"),
hr_review. `boss_leave`, `boss_return`, `end_day` are handled by World (Director gets onBossLeft/onBossReturned).
`onBossLeft` → log "🏌️ Sếp ra ngoài: {reason}" + normal-priority group_chat soon ("sếp đi rồi anh em ơi").

## 6. AI layer (ai owner)

### 6.1 `reserve(priority)`
```
offline mode (no key):  high → 'offline';  low/normal → 'offline' if ≥ offlineMinSeconds since last grant, else null
llm mode:
  costToday ≥ dailyBudgetUsd           → high: 'offline', else null (skipped++)
  llmOnlyWhenWatched && viewers === 0  → high: 'offline', else null (skipped++)
  inflight ≥ maxConcurrentLlm          → high: 'llm' (queues), else null
  low: ≥ minSecondsBetweenLlm since last LLM grant; normal: ≥ half of that; high: always
  grant 'llm' (record time)
```
`generateRecap` / `generateCandidate` use LLM when in llm mode and under budget, else offline.
v3 `generateBeats(req, ctx)`: LLM khi llm mode, dưới ngân sách **và** `viewers > 0` (không ai xem → `offlineBeats`); task `beats` rẻ nên
router dùng thứ tự provider thường (không ưu tiên `strong`); deadline 20 s, ≤ 450 token ra, system prompt riêng tĩnh (~280 token);
tính vào `usage()`; không bao giờ throw (lỗi / JSON hỏng / không beat hợp lệ → offline).

### 6.2 LLM call (`llm.ts` + `router.ts`) — multi-provider, free-tier friendly
**Config** (`src/config.ts`): `AI_PROVIDERS=gemini,groq` = ordered provider names; per name `AI_<NAME>_BASE_URL`,
`_API_KEY`, `_MODEL`, optional `_RPM` / `_RPD` / `_TPD` (self-imposed caps), `_PRICE_INPUT_PER_M` /
`_PRICE_CACHED_INPUT_PER_M` / `_PRICE_OUTPUT_PER_M` (default 0 = free; OpenAI endpoint + known model → price table),
`_REASONING_EFFORT`, `_TIER` (`normal` | `strong`), `_JSON` (`schema` | `object`), `_LABEL`. Providers without a key are
skipped with a startup note. Empty `AI_PROVIDERS` → one provider built from legacy `OPENAI_*` (named `openai`, or
`gemini` / `groq` when the base URL points there). `CONFIG.providers: ProviderConfig[]` is the source of truth; the old
fields (`openaiKey`, `openaiBaseUrl`, `model`, `price`, …) mirror the primary provider. **`openaiKey === ''` turns AI
off** (legacy kill-switch used by `scripts/smoke.ts`); tests build configs with `withProviders(CONFIG, [...])`.

**Client** (`llm.ts`): `new OpenAI({ apiKey, baseURL, timeout: 20000, maxRetries: 0 })` per provider; `attempt()` =
exactly one `chat.completions.create` with `[system, user]`, `response_format` json_schema (strict) or json_object,
`max_completion_tokens` scene 1300 / candidate 700 / recap 800 (caps, not costs; reasoning models ×3 + `reasoning_effort`), `temperature: 1`
for non-reasoning models, `prompt_cache_key` only for api.openai.com. Learns per provider which optional params the
server rejects (400 → drop and retry) and when `max_tokens` must be used. Usage → cost at that provider's prices
(estimated from characters when the server returns no usage). Content errors (empty / refusal / bad JSON) throw
`LlmError` carrying the usage so tokens are still counted. The client passes a wrapping `fetch` to the SDK that unwraps
Gemini's array-form error bodies (`[{"error":{…}}]` → `{"error":{…}}`) so status/message/code are visible to the router.

**Router** (`router.ts`): `pick(task, priority)` = first provider that has a key, is not cooling down and is under RPM
(sliding 60 s), RPD and TPD (counters keyed by the provider's quota-reset day: Gemini = date in America/Los_Angeles,
because Google resets free-tier daily quotas at midnight Pacific; other providers = VN date, approximate). `strong`-tier
providers go first for priority `high`, recap and candidate; otherwise configured order. `complete(req)` tries providers
in that order **inside the same request** while time remains (per attempt `min(20 s, remaining − 0.3 s)`, no new attempt
under 2.5 s left — 6 s for reasoning models, ≤ 3 HTTP attempts, never past the brain deadline). Every attempt counts
toward RPD and `calls` even on failure. Error policy per provider: **429** → cooldown = `Retry-After` (seconds or HTTP
date, also "retry in 32s" / "try again in 1m2s" hints; honoured for daily quotas too — Groq's TPD/RPD hints are exact)
else backoff 30 s → 60 s → 120 s … max 15 min; **daily** quota (per day / daily / RPD / TPD / "quota exceeded") with no
hint → Gemini cools down until next midnight Pacific (re-probed at most every 6 h), other providers re-probe after 1 h;
Gemini's "retry in 27s" hint on a daily-quota 429 is known to be wrong and is ignored (hints < 10 min on a daily quota of
a provider with a known reset time). **401 / 403 / 404** (or Gemini's 400 "API key not valid" / "Please pass a valid API
key") → disabled 1 h with a Vietnamese log naming the `.env` variable. **5xx / network / timeout** → 20 s then backoff,
except a timeout inside an attempt window that the brain deadline truncated below 20 s (fallback provider got only a few
seconds) — that is not charged to the provider. **400 that explicitly rejects response_format / json_schema** → remember
json_object for that provider (24 h, persisted) and retry once; Groq's `json_validate_failed` (model produced
schema-invalid JSON) is a content error (no cooldown, no format change, next provider); any other 400 → 20 s backoff,
format unchanged. **429 "Request too large … Limit L, Requested R"** (Groq free tier caps *output* tokens per minute per
model — e.g. `qwen/qwen3.8-27b` OTPM 1000 while a reasoning-model scene asks 1300 × 3 = 3900 — or total TPM): not a
cooldown. The router (`parseTooLarge`) remembers a per-provider `maxOutputTokens` cap (OTPM: 90 % of L; TPM: current budget
minus the overshoot and a 10 % margin; unparsable: half), retries the **same provider immediately** with the reduced
`max_completion_tokens` (≤ 2 shrinks per request; a cap below 256 → skip that provider for this request, no penalty),
and persists the cap for 7 days in the snapshot (`maxOutputTokens` / `maxOutputUntil`). Success resets that provider's backoff. A global concurrency queue (`MAX_CONCURRENT_LLM`) spans all
providers.

**Brain** (`brain.ts`): `mode()` = `llm` iff any provider has a key. `reserve()` falls back to offline pacing when no
provider is available right now (all cooling down / exhausted) or the breaker is open; the Director never sees which
provider answered. The circuit breaker counts only whole-request failures (every provider tried failed), so one broken
provider never pauses the system. `DAILY_BUDGET_USD` is a global cap across providers (free ones cost 0). Keys of every
provider are redacted in `lastError` / logs (`describeError(e, keys)`, plus generic `sk-` / `gsk_` / `AIza` / `AQ.` /
Bearer / `key=` patterns).

**Stats** (`UsageStats`, additive): totals aggregate all providers; `model` = active provider's model; `mode` = `llm` iff
some provider is usable **now** (so the existing chip works untouched); new optional `activeProvider` (label) and
`providers: ProviderStats[]` `{ name, label, model, enabled (usable now), calls, failures, inputTokens, outputTokens,
costTodayUsd, rpdUsed, rpdLimit?, tpdUsed, tpdLimit?, cooldownUntil (ms, 0 = none), cooldownReason?, format, lastError? }`.
`serialize()/restore()` keep per-provider daily counters (date-keyed), cooldowns, json format choice and totals; v1
snapshots (single provider) and unknown providers fold into a carry-over total; garbage input is ignored.

### 6.3 Prompts (`prompts.ts`) — Vietnamese
- **System prompt is static** for the whole process (same string every call → OpenAI prompt cache): role
  ("biên kịch sitcom văn phòng real-time"), company description (`COMPANY_INFO`), style rules, effect rules,
  JSON format rules. Put nothing dynamic in it (no time, no states). Aim ≥ 1024 tokens is fine but not required.
- Style rules: natural spoken Vietnamese; short lines (≤ 25 words, ideally 6–18); each character keeps their voice
  and correct xưng hô (anh/chị/em/sếp…); humor, khịa, than thở, nói xấu sau lưng when fitting; Gen Z slang only for
  Gen Z characters; group chat = chat style (viết tắt, emoji, teencode nhẹ); company chat = lịch sự, nịnh sếp; light
  swearing only ("trời ơi", "má ơi"); no sexual content, no discrimination, no real people/brands/politics; no moral
  lessons; no narration or stage directions in text; don't repeat recent topics; every line moves the scene forward;
  concrete details (project name, deadline, bug, KPI, food, traffic, gold price...).
- **User prompt is compact and dynamic**: time/weekday, boss status, project status, channel + location,
  situation, topic hint, participants (id, name, role, gender, age, bio ≤ 200 chars, speech style, current activity,
  energy/mood/stress, KPI %, feelings only toward other participants / aboutId, last 3 memories), absent person
  being discussed, rumor (“kể lại nhưng thêm mắm dặm muối, sai lệch đi một chút”), product (“một người nhắc tự nhiên,
  1 câu, không quảng cáo lộ liễu, không nói giá/link, đánh dấu product=true”), recent summaries to avoid,
  line count, allowed speaker ids, which effects are allowed.
- Scene JSON (strict schema; all keys required, nullable where optional):
  `{ lines:[{speaker,text,emote|null,product:boolean}], summary, relationshipChanges:[{from,to,delta,reason}],
     moodChanges:[{id,delta}], memories:[{id,text}], kpiChanges:[{id,delta}], rumor:{aboutId,text}|null,

  bao lâu, lúc nào, thấy gì), người kia khịa hoặc nghi ngờ ("ăn hoa hồng hả"), hỏi giá nhưng không ai nói giá, "để tối săn sale";

  > LUẬT TIN THẬT (bắt buộc): chỉ nói cảm nghĩ, ý kiến, cảm xúc về tin ĐÚNG NHƯ báo đăng ở trên; không thêm sự thật, con số, phát ngôn,

  > không đoán kiểu "chắc là bị…"; không chế giễu người thật có tên (khịa tình huống thì được); dẫn nguồn: "theo báo X đăng", "nghe nói
  > trên báo", "tui chưa đọc kỹ"; 4–8 câu kiểu tám chuyện văn phòng, mỗi người phản ứng theo tính cách, sở thích của mình và được liên hệ
  > sang chuyện của mình (đội bóng mình mê, game mình chơi, trend mình quay); không chính trị, tôn giáo.
  Không render `topicHint` cho news_chat.
- **hr_review** (`dossierLines()`): 1 dòng / người (`KPI 7 ngày`, lowStreak, warnings, bắt lười, mood/stress, thái độ, **`được phép: …`**) + chú giải
  hành động gọn; yêu cầu `hrDecisions` chỉ dùng hành động trong `được phép`, AI được trả `[]`. Giữ `maxLines ≥ 7` để bàn được 2 người.
- **Beats** (`buildBeatsSystemPrompt()` tĩnh + `buildBeatsUserPrompt()` 4 bậc rút gọn, ngân sách 410 token): situation / menu / mạch mở /
  beat gần đây / roster → `{beats:[{kind, a|null, b|null, intensity:int, note}]}` (`BEATS_SCHEMA`, tên `ke_hoach_bien`).
- Kích cỡ (ước lượng 2.7 ký tự/token): system ≈ 1615 (tĩnh, cache); news_chat 2–3 người ≈ 2.7–2.85k tổng; hr_review 3–8 hồ sơ ≈ 2.7–3.05k;
  resign/raise ≈ 2.4k; promotion/layoff 3–5 người ≈ 2.5–2.95k; beats ≈ 0.7k tổng.
- **Offline v3** (`offline.ts`): `bNews` (86 mẫu: mở / phản ứng theo nhóm tin / liên hệ đời mình theo vai / chốt — chỉ dùng tiêu đề + nguồn),
  `bHrReview` (quyết định ngẫu nhiên có trọng số trong `allowed`, thoại khớp `hrDecisions`), `bResign` / `bRaise` (xác suất theo mood, quan hệ,
  KPI, doanh thu), `bPromotion`, `bLayoff`; `offlineBeats()` 1–2 beat có trọng số, né kind vừa dùng.

### 6.4 Sanitizing (brain)
Map speaker names→ids if the model used names; drop lines with non-participant speakers; strip quotes and
"Tên:" prefixes; max 220 chars; need ≥ 2 lines (and ≥ 2 distinct speakers when ≥ 2 participants) else offline
fallback; cap at maxLines+2. Clamp/filter effects to allowed kinds and known ids. `product` true on at most one line
and only if `req.product`. Missing summary → derive one.
- **Verdict theo loại (v3, `normalizeVerdict`)**: interview `hired|rejected` (thiếu → `hired`), resign_talk `stay|leave` (thiếu → `stay`),
  raise_request `approved|denied` (thiếu → `denied`), loại khác → `null`; hiểu từ đồng nghĩa tiếng Việt ("nhận", "từ chối", "ở lại", "nghỉ"…).
- **`hrDecisions` (v3, `sanitizeHrDecisions`)**: chỉ hr_review (loại khác → `null`); id lạ bỏ; alias / hành động sai → `none`; hành động không
  thuộc `allowed` của người đó → `none`; `open_position` id '' chỉ khi có ai cho phép; ≤ 1 / người, ≤ 6; `reason` ≤ 100 (thiếu → mặc định).
- **Lưới an toàn tin thật (v3, `NEWS_BLOCK_RE` / `isNewsSafe`)** khi `req.news`: bỏ câu / ký ức / tóm tắt chứa bị bắt · bắt giữ · tạm giam ·
  khởi tố · truy tố · lừa đảo · ngoại tình · ma túy · giết người · hiếp dâm · tự tử · đánh bạc (trừ thành ngữ văn phòng "bị bắt lười / quả tang /
  gặp / phải…"); còn < 2 câu an toàn → fail → offline (`lastError` "luật tin thật").
- **Beats (v3, `sanitizeBeats`)**: `kind` phải ∈ menu (so khớp gấp dấu); `a`/`b` tra theo tên / id roster; `intensity` kẹp 1..3 (mặc định 2);
  `note` ≤ 140 (thiếu → mô tả menu); bỏ trùng; ≤ 3; không beat hợp lệ → fail → offline. `emergencyScene` / `emergencyBeats` cho mọi loại mới.

## 7. Server & protocol (sim owner)

- `GET /` and static files from `public/` (safe path resolution, no traversal, correct content types, `no-cache`).
- `GET /go/:productId?src=...` → only known product ids → `world.recordClick(id, src)` → 302 to `product.url`;
  unknown → 404. (No open redirect.)
- `GET /api/health` → `{ ok: true, mode, viewers, day, minute }`.
- `GET /api/stats` → `{ clicks, clicksBy: {productId: n}, clicksBySource: {src: n}, clicksByProductSource: {productId: {src: n}},
  ai: { mode, model, activeProvider, calls, failures, costTodayUsd, costTotalUsd, budgetUsd, skipped, providers: ProviderStats[] }, day }`
  (số lượt bấm link affiliate theo sản phẩm và theo nguồn `src` = `showroom` / `sidebar` / `scene` / `desk`, để chủ web theo dõi;
  `providers` = chi tiết từng provider như `status.ai.providers`, không bao giờ chứa key).
- `hello.rules` (tuỳ chọn) = `{ kpiLowRatio, kpiWarnDays, kpiFireDays }` từ `.env` → client vẽ ngưỡng KPI và huy hiệu
  "🔥 nguy cơ bị đuổi" đúng cấu hình (mặc định 0.7 / 2 / 3 nếu thiếu).
- `hello.products` (v2) = `ShowroomProduct[]` (`src/sim/showroom.ts → buildShowroomProducts()`, World tính 1 lần lúc khởi
  động): ưu tiên `content.getShowroomProducts()`; nếu chưa có / trả về rỗng thì tự dựng từ `getProducts()` — `category` lấy từ
  `data/products.json`, thiếu thì suy từ tag (`lam-dep`/`my-pham`/`skincare`/`son` → kệ làm đẹp, `cong-nghe`/`gadget` → kệ
  công nghệ; không thuộc kệ nào → không lên kệ). `url` **luôn** `/go/<id>?src=showroom` (client đổi thành `src=sidebar` cho
  tab 🛍️); `slot` thiếu → số trống nhỏ nhất của kệ; `note` thiếu → dùng `pitch`; sắp theo kệ (làm đẹp trước) rồi slot; tối đa 40.
- `hello.map` = `MAP_DATA` (v2 có thêm `spots`; rooms `showroom` + `wc`, furniture `shelf_beauty` / `shelf_tech` /
  `display_table`, không còn `toilet` / `sink`).
- `hello.news` (v3) = `getNews().recent(5)` (`NewsRef[]`, mới nhất cuối); `PublicAgent` v3 có thêm `traitBase`, `probationUntilDay`, `bonuses`,
  `promotions` (tuỳ chọn). `GET /api/news`, `GET /api/history` — §10.5.
- WebSocket on path `/ws` (`ws` package, same HTTP server). On connect send `world.hello()`, update viewer count
  (`world.setViewers(n)`). Messages: JSON ≤ 2 KB, validated `ClientMsg`; dev actions only if `CONFIG.devPanel` **và** (v3) socket có quyền dev
  theo `DEV_TOKEN` (`/ws?dev=<token>`, `hello.dev` theo từng socket — §10.5); dev event names gồm `news`, `showrunner`;
  speed ∈ {1,2,5,10}. Broadcast helper skips sockets with `bufferedAmount > 1 MB`.
- Persistence: if `CONFIG.persist`, `world.load()` at startup; `world.save()` every 60 s and on SIGINT/SIGTERM
  (then exit). State file JSON `{ version: 1, savedAt, world, director, brain }`; any problem → fresh start + warning.
- Startup log (Vietnamese): URL, chuỗi provider thật ("Gemini (model) → Groq (model) → câu mẫu offline" — không ghi "GPT"
  trừ khi provider là OpenAI) hoặc OFFLINE, budget, số sản phẩm trên kệ phòng trưng bày.

Message cadence: `frame` 200 ms, `agents` + `status` 2 s, `log` / `scene` / `toast` / `recap` / `rumors` on event.
`FrameAgent` = `[id, x(2 decimals), y, dir, activity, emote, flags]` (flags 1 = walking, 2 = onPhone, 4 = in scene,
8 = hidden — đang trong WC, client không vẽ); only present agents are included (kể cả người ẩn, để client biết WC "Có người").

  theo 1 chuyển hướng, tự giải nén gzip/deflate/br, lỗi → reject thông điệp tiếng Việt); `parseRss(xml, group, { now?, feedUrl? }): NewsItem[]`
  (RSS 2.0 `<item>` + Atom `<entry>` tối giản; CDATA, entity, bỏ HTML; `id = sha1(url chuẩn hoá — bỏ utm_*/#).slice(0, 12)`;
  `summary ≤ 200` cắt ở ranh giới từ; `source` theo tên miền: VnExpress / Tuổi Trẻ / Thanh Niên / GameK…; `publishedAt` hiểu RFC 822,
  `GMT+7`, năm 2 chữ số, ISO, `11/1/2026 2:20:00 PM` — không ghi múi giờ → giờ Việt Nam; không đọc được → `now`); nhóm `the_thao` có từ khoá
  bóng đá (V-League, Ngoại hạng, Champions League, tuyển Việt Nam, ghi bàn…) → `category = 'bong_da'`. `fetchFeed(feed, opts)`.
- `filter.ts`: `judge(item, { now?, maxAgeDays?, allowShowbiz?, blocklist? }): { ok: true } | { ok: false; reason: 'invalid'|'blocked'|'old'|'showbiz_off'|'showbiz'; keyword? }`,
  `filterNews(items, opts) → { kept, dropped }`. `BLOCKLIST` (pháp lý, bạo lực, tang sự / sức khoẻ, chính trị, đời tư, 18+), `SHOWBIZ_PRIVATE`
  (đời tư / cơ thể — chỉ nhóm giai_tri), `SHOWBIZ_ALLOW` (giai_tri **phải** khớp: phim, nhạc, show, gameshow, thời trang, trend, concert, MV…).
  So khớp theo ranh giới từ: từ đơn CÓ dấu; cụm ≥ 2 từ mà mọi tiếng ≥ 3 chữ cái KHÔNG dấu (bắt "khoi kien", "bat giu"); cụm có tiếng ngắn
  ("bản án", "đi tù") có dấu. `BLOCK_EXCEPTIONS`: "công an" trong tên CLB (Công An Hà Nội / TP.HCM) không chặn. Tiện ích: `stripDiacritics`,
  `normText`, `matchKeyword`, `findKeyword`, `findBlocked`.
- `store.ts` — `class NewsStore` + singleton `getNews()` (cấu hình từ CONFIG, **không tải gì** cho tới khi `start()`), `configureNews(partial)`:
  - `start()` (lần đầu sau 20 s rồi mỗi `refreshMinutes`; timer `unref`) / `stop()` / `refresh(): Promise<RefreshReport>` (song song mọi feed,
    lỗi từng feed → giữ tin cũ, `console.warn` tối đa 1 lần / giờ / feed; log 1 dòng khi có tin mới).
  - `pick(categories?: NewsCategory[], exclude?: Set<string>): NewsItem | null` — ngẫu nhiên một nhóm còn tin (mặc định mọi nhóm; `the_thao`
    gồm cả `bong_da`), rồi ngẫu nhiên trong **5 tin mới nhất** của nhóm; bỏ tin đã `markUsed` / trong `exclude` / quá hạn. Trả về bản sao.
  - `markUsed(id)` (trần 500 id, lưu file) · `isUsed(id)` · `recent(n = 5): NewsRef[]` (tin đã bàn gần nhất, **mới nhất cuối**) · `find(id)` ·
    `items(category?)` (mới nhất trước) · `size()` · `counts()` · `status()` · `inject(items): { added, dropped }` (test, không mạng) · `clear()`.
  - ≤ 40 tin / nhóm (kho đầy chỉ nhận tin mới hơn tin cũ nhất). `serialize()` / `restore()` do **World** gọi — nằm trong `data/state.json`
    (`world.news`): id đã dùng, 20 tin gần đây, ≤ 12 tin / nhóm.
  - `toNewsRef(item)`, `expandCategories(cats)`, `sanitizeNewsItem(raw)`, `ALL_CATEGORIES`.
- Mẫu RSS cho test: `scripts/fixtures/news/{tuoitre-the-thao,gamek-home,vnexpress-giai-tri}.xml` (≤ 55 KB mỗi file, tải 2026-11-01).
  `npm run test:news` (`scripts/test-news.ts`, 76 khẳng định, không mạng).

### 10.3 Lưu trữ dài hạn — `src/sim/archive.ts`

`class Archive` + singleton `getArchive()` — **tắt** cho tới khi `configure({ enabled: true, dir, keepDays, gzipAfterDays }).start()`
(server và smoke gọi; test-llm / test-router không bao giờ ghi file).
- `record(kind: string, data: unknown): boolean` — xếp vào hàng đợi (trần 5000 dòng, vượt → bỏ dòng cũ nhất); dòng =
  `{"ts":<ms>,"kind":"log|kpi|recap|hr|beat|news|…","data":…}` vào `HISTORY_DIR/YYYY-MM-DD.jsonl` (**ngày theo giờ Việt Nam**).
  World ghi `log` (mọi LogEntry) và `kpi` (`{ day, weekday, results }` cuối ngày); Director ghi `recap` / `hr` / `beat` / `news` tuỳ ý.
- Ghi theo lô mỗi 2 s (`fs/promises.appendFile`, không chặn tick); lỗi → `console.warn` 1 lần / 10 phút, bỏ lô. `flush(): Promise<void>`,
  `flushSync()` (khi tắt server), `stop()`.
- `rotate(): Promise<{ gzipped, deleted }>` — lúc khởi động (sau 5 s) và khi sang ngày mới: gzip file cũ hơn `gzipAfterDays` (không đụng file
  hôm nay; nếu `.gz` đã có thì nối thêm thành viên gzip), xoá file cũ hơn `keepDays`.
- `listDays(): Promise<{ date, count, bytes, gz }[]>` (đếm dòng 1 lần, nhớ theo mtime) · `readDay(date, { offset?, limit? ≤ 5000 }): Promise<ArchiveEntry[]>`
  (đọc `.jsonl.gz` rồi `.jsonl`, bỏ dòng hỏng) · `hasDay(date)` · `stats()` · `vnDate(ms)`, `isDateString(s)`, `HISTORY_READ_MAX = 5000`.
- Ước lượng: ~230 B / dòng; chế độ nén (65 ngày game / ngày thật) ≈ 5–6 MB / ngày thật trước nén, ~0,7 MB sau gzip.

### 10.4 World (`src/sim/world.ts`, `behavior.ts`) — câu chuyện tự phát triển

- **Tính cách lần đầu** (`freshInit`, `STORY_RANDOMIZE_TRAITS`): mỗi trait = roster ± U(−0.15, 0.15), kẹp 0.05..0.95, làm tròn 2 chữ số;
  `traitBase` = bản sao. Đội hình ban đầu có trait công việc cực đoan được kéo về vùng bình thường **trước** khi thêm nhiễu
  (`diligence < 0.45 → U(0.45, 0.55)`, `laziness > 0.6 → U(0.5, 0.6)`) để không ai bị định trước là người kém (kiểm chứng 10 hạt giống × 3 ngày:
  5 người khác nhau đứng cuối KPI). Không áp cho người do AI sinh (`addAgent`: `traitBase = traits`). Khôi phục file cũ: `traitBase = traits`.
- **Hệ số ngày** `dayFactor ~ U(0.75, 1.2)` mỗi người mỗi ngày (`planDay`), nhân vào `kpiRate()` (`behavior.dayFactorOf`); cực đoan
  (< 0.82 / > 1.13, tối đa 2 người / ngày) → log tiếng Việt lúc tới công ty (😪 "hôm nay Bảo bị cảm, làm uể oải" / ✨ "Vy hôm nay sung lắm…") + ký ức.
- **Sự kiện cá nhân** (≈ 1 / 3 ngày game cho cả văn phòng, `rollPersonalEvent`): `sick` (đến trễ 30–60', dayFactor ≤ 0.6–0.8, energy −15; 🤒),
  `traffic` (đến trễ 20–45'; 📱 "nhắn vào nhóm: kẹt xe quá…" trước khi tới), `heartbreak` (mood −20, diligence −0.15 **trong ngày** qua
  `Rt.tempTraits`, hoàn lại hôm sau; 💔), `angry_client` (chỉ sales: stress +15, mood −8; 😤), `lottery` (mood +20; 🎉). Tất cả = `log` kind `event`
  + `addMemory` → Director đọc `memories`.
- **WorldApi bổ sung** (World là implementer duy nhất; chưa thêm vào interface `WorldApi` trong `types.ts` — xem báo cáo):
  - `driftTrait(id, key: keyof Traits, delta): number` — mỗi lần ≤ ±0.2, kết quả kẹp `traitBase ± 0.25` (và 0.05..0.95); trả giá trị mới
    (`NaN` nếu không có người); `STORY_TRAIT_DRIFT=false` → không đổi.
  - `setRole(id, roleLabel, kpiTarget)` — chức danh (≤ 60) + mục tiêu (30..5000), `promotions++`.
  - `removeAgent(id, reason: 'fired' | 'resigned' | 'laid_off' = 'fired')` — tổng quát `fireAgent`: status `'fired'`, đi ra cửa với 📦
    "ôm thùng đồ ra về" / 👋 "nộp đơn nghỉ việc…" / 📦 "bị cắt giảm…"; sếp / HR không bao giờ bị loại. `fireAgent(id)` = `removeAgent(id, 'fired')`.
  - `setProbation(id, untilDay | null)` → `probationUntilDay` (hết hạn ra sao do Director quyết). `grantBonus(id)` → `bonuses++`. `headcount(): number`.
  - `getArchive(): Archive` — archive dùng chung để Director ghi `record(kind, payload)` (recap / hr / beat / news…).
- Lưu file: `traitBase`, `dayFactor`, `probationUntilDay`, `bonuses`, `promotions`, `Rt.personal / tempTraits / dayNote / leaveReason`,
  `world.news` (kho tin). `hello.news = getNews().recent(5)`. `DEV_EVENTS` có `news`, `showrunner` → `director.onEvent`.

### 10.5 Server (`src/server.ts`)

- **DEV_TOKEN**: quyền dev tính theo socket lúc nối `ws(s)://host/ws?dev=<token>` (so sánh thời gian cố định, không ghi token ra log).
  `hello.dev` = true chỉ cho socket dev (hoặc mọi socket khi `DEV_TOKEN` rỗng và `DEV_PANEL=true`); `DEV_PANEL=false` tắt hẳn. Lệnh dev từ
  socket không có quyền bị bỏ qua (đếm, `console.warn` ≤ 1 lần / phút). Frontend cần chuyển `?dev=` từ URL trang sang URL WebSocket.
- `GET /api/news` → `{ enabled, feeds, refreshMinutes, lastRefreshAt, lastOkAt, lastError, refreshes, counts, total, used, recent: NewsRef[], items: (NewsRef & { publishedAt })[] }` (`?limit` ≤ 240).
- `GET /api/history` → `{ enabled, days: [{ date, count, bytes, gz }], stats }`; `GET /api/history?date=YYYY-MM-DD[&offset&limit]` →
  `{ date, offset, limit, count, entries: [{ ts, kind, data }] }` (≤ 5000 / lần); sai định dạng → 400, không có ngày → 404.
- Khởi động: archive `configure().start()` **trước** `new World()`; `getNews().start()` sau `world.start()` (nếu `NEWS_ENABLED`); tắt server:
  `news.stop()`, `world.save()`, `archive.stop()` (ghi nốt). Log khởi động thêm dòng 🗄️ / 📰 / 🛠️ (không in token).
